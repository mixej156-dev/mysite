# CLAUDE.md — Staking Platform: Frontend Design Prototype

## 0. О проекте

Многостраничный сайт крипто-компании по стейкингу (рабочее название: **{BRAND_NAME}**, заменить позже).
Это **только дизайн-прототип**: без бэкенда, без базы данных, без реальных API и блокчейн-интеграций.
Цель — максимально убедительный, выверенный визуально и анимационно фронтенд, который можно показать клиенту/инвесторам и позже подключить к реальному бэкенду.

Язык интерфейса и контента сайта: **английский** (если не указано иное). Язык общения со мной: русский.

## 1. Жёсткие ограничения (никогда не нарушать)

- НЕТ бэкенда: никаких серверных баз данных, ORM, API-роутов с реальной логикой, внешних платежей, web3-кошельков, реальных запросов к блокчейну.
- НЕТ реальных секретов, ключей, `.env` с данными.
- Все данные (ставки, APY, TVL, балансы, транзакции, команда, статьи блога) — **моковые**, лежат в `/src/data/*.ts` и импортируются локально.
- Авторизация — **фейковая**: любая пара email/пароль «проходит», состояние хранится в `localStorage` (+ простой React Context). Никакой валидации «настоящих» пользователей.
- **Не показывать пометки «Demo data» / «Demo»** в интерфейсе (решение заказчика, 2026-10-17). Вместо них — нейтральные формулировки: «estimates, not an offer or a forecast», «reference prices», предупреждение о рисках в футере. Идентификаторы в коде (`DEMO_TODAY`, `demo_session`) пользователю не видны, их можно оставить.
- Не копировать у референсов (Ondo Finance, Spreadefi) тексты, логотипы, иллюстрации, названия продуктов. Берём только **принципы структуры и визуального языка**, всё содержимое оригинальное.
- Не выдумывать юридически значимые заявления (лицензии, аудиты конкретных фирм, гарантированную доходность). Использовать нейтральные формулировки + блок рисков.

## 2. Технологический стек

- **Next.js (App Router) + TypeScript**
- **Tailwind CSS** + CSS-переменные для токенов
- **Framer Motion** — анимации (появление секций, hover, переходы между страницами, счётчики)
- **lucide-react** — иконки
- **Recharts** (или аналог) — графики в дашборде на моковых данных
- **next/font** — шрифты (self-hosted через Google Fonts)
- Без UI-китов, которые навязывают «типовой» вид. Допустимо использовать Radix UI primitives (доступные dropdown/dialog/tabs) со своей стилизацией.

## 3. Обязательный порядок работы

1. **Перед любым фронтенд-кодом загрузить скилл `frontend-design`** и сформулировать дизайн-направление письменно (в `/docs/design-direction.md`).
2. **Сначала дизайн-система, потом страницы** (см. раздел 5). Страницы нельзя начинать, пока нет токенов и базовых компонентов.
3. **Одна страница за раз.** После каждой — визуальная проверка (раздел 8) и git-коммит.
4. Перед крупными шагами использовать Plan Mode и кратко согласовывать план.
5. Никаких «значений от балды»: цвета, отступы, радиусы, тени, размеры шрифта — только из токенов.
6. После каждого завершённого этапа: `git add -A && git commit -m "..."`.

## 4. Дизайн-направление

Референсы по духу (НЕ копировать, только ориентироваться):

**Ondo Finance — институциональный, «взрослый» финтех:**
- Крупная уверенная типографика в hero, короткий манифест-заголовок.
- Много воздуха, чёткая сетка, ощущение надёжности и «институционального качества».
- Полоса логотипов партнёров (бесконечный marquee).
- Блоки с живыми метриками (TVL, число активов, APY) с анимацией счётчиков.
- Секция «Trust & Security»: нумерованный список принципов (01–05).
- Карточки продуктов с метриками и кнопкой «Discover».
- Секции с цитатами партнёров, блок инсайтов/блога, подписка на рассылку, многоколоночный футер.

**Spreadefi — DeFi-стейкинг, продуктовая ясность:**
- Простая схема «как это работает» в 4 шага (Stake → Pool works → Revenue → Rewards).
- Акцент на пулах ликвидности, ежедневных выплатах, прозрачности и возможности вывода.
- Страницы: стейкинг, swap, API/для разработчиков, документация.

**Итоговый стиль (зафиксировать в design-direction.md):**
- Тёмная и светлая секции чередуются; основной фон — глубокий тёмный (почти чёрный с лёгким оттенком), акцент — один фирменный цвет + нейтральные.
- Избегать: фиолетово-розовых градиентов «по умолчанию», системных шрифтов, шаблонного «AI-вида», перегруженных неоновых эффектов.
- Шрифты: выбрать выразительную пару (display + text) через next/font; не Inter/Roboto/Arial по умолчанию. Моноширинный — для цифр, адресов, хешей.
- Числа в дашборде — табличные (`font-variant-numeric: tabular-nums`).
- Стекло/размытие и тонкие границы — умеренно. Тени мягкие. Радиусы единые.
- Анимации: плавные, сдержанные (200–600 мс), easing единый; уважать `prefers-reduced-motion`.

## 5. Дизайн-система (создать первой)

Папка `/src/design-system` и страница-витрина `/styleguide`:

- **Токены** (CSS variables + Tailwind config): цвета (bg, surface, border, text, muted, accent, success, warning, danger), типографическая шкала, отступы (шкала 4/8), радиусы, тени, z-index, длительности/easing анимаций.
- **Тёмная/светлая тема**: токены для обеих; переключатель в хедере.
- **Базовые компоненты**: Button (primary/secondary/ghost, размеры, loading), Input, Select, Checkbox, Toggle, Tabs, Modal, Dropdown, Tooltip, Badge, Card, Table, Tag, Accordion, Progress, Skeleton, Toast, Pagination.
- **Составные блоки**: Header (с мега-меню), Footer, Hero, StatCard (анимированный счётчик), LogoMarquee, FeatureGrid, StepsFlow, PricingTable/TierCards, TeamCard, BlogCard, CTASection, Newsletter, FAQ, TestimonialSlider, Breadcrumbs.
- **Дашборд-компоненты**: Sidebar, Topbar, BalanceCard, ChartCard, StakePositionsTable, RewardsFeed, ActivityList, EmptyState.
- На `/styleguide` показать все компоненты во всех состояниях и обеих темах.

## 6. Карта сайта

**Публичная часть**
- `/` — Главная: hero-манифест, метрики, продукты/стейкинг-пулы, «как это работает» (4 шага), partners marquee, Trust & Security, цитаты/отзывы, инструменты, последние посты блога, подписка, CTA.
- `/staking` — Обзор стейкинга: список пулов/активов (фильтры, сортировка, APY, срок, мин. сумма), карточки.
- `/staking/[asset]` — Детальная страница пула: описание, параметры, график APY, риски, FAQ, CTA «Stake».
- `/tools` — Инструменты (хаб): калькулятор доходности, сравнение пулов, конвертер, gas-оценка (всё на моках).
- `/tools/calculator` — интерактивный калькулятор стейкинга (слайдеры, график роста).
- `/tools/compare` — сравнение пулов.
- `/about` — О компании: миссия, ценности, история (timeline), цифры.
- `/team` — Команда (карточки, роли, соцссылки-заглушки) + вакансии/карьера.
- `/security` — Trust & Security: принципы, процессы, custody (нейтральные формулировки), bug bounty-заглушка.
- `/blog` — Список статей (категории, поиск, пагинация), `/blog/[slug]` — статья.
- `/docs` — Заглушка документации с боковой навигацией и несколькими статьями.
- `/faq`, `/contact`, `/legal/terms`, `/legal/privacy`, `/legal/risk-disclosure`.
- `/404` — оформленная страница ошибки.

**Авторизация (фейковая)**
- `/login`, `/register` — формы. Любой ввод = успешный вход. Редирект в `/dashboard`.
- `/forgot-password` — экран с имитацией отправки письма.

**Личный кабинет (защищён фейковым гардом: без «сессии» → редирект на /login)**
- `/dashboard` — Обзор: общий баланс, график, активные позиции, награды, активность.
- `/dashboard/stake` — Создание стейка (форма с выбором пула/суммы, модалка подтверждения, имитация успеха).
- `/dashboard/positions` — Таблица позиций, детали, «Unstake» (имитация).
- `/dashboard/rewards` — История и график наград.
- `/dashboard/transactions` — История транзакций (фильтры, пагинация).
- `/dashboard/wallet` — Кошелёк: балансы активов, Deposit/Withdraw (имитация, модалки).
- `/dashboard/referrals` — Реферальный блок.
- `/dashboard/settings` — Профиль, безопасность (2FA-UI), уведомления, тема, API-ключи (фейковые).

## 7. Фейковая авторизация и данные

- `AuthContext` + `localStorage` ключ `demo_session`. Любой email/пароль → создаётся сессия с именем из email.
- Гард для `/dashboard/*`: клиентская проверка сессии, редирект на `/login`.
- Logout очищает сессию.
- Действия «Stake / Unstake / Deposit / Withdraw» только меняют локальное состояние (Context + localStorage) и показывают Toast; никаких внешних вызовов.
- Моковые данные: `/src/data/pools.ts`, `positions.ts`, `transactions.ts`, `team.ts`, `posts.ts`, `faq.ts`, `partners.ts`, `metrics.ts`. Реалистичные, но очевидно демонстрационные.
- Партнёрские «логотипы» — собственные нейтральные плейсхолдеры, не логотипы реальных компаний.

## 8. Визуальная проверка (обязательно после каждой страницы)

Использовать **Playwright MCP** для скриншотов:
1. Запустить dev-сервер (`npm run dev`).
2. Снять скриншоты страницы на ширинах **375 / 768 / 1440 px**, в светлой и тёмной теме.
3. Просмотреть скриншоты, найти проблемы: выравнивание, отступы, обрезка текста, переполнение, контраст, поломанный адаптив.
4. Исправить и повторить, пока визуально не станет чисто.
5. Проверить состояния: hover, focus, active, disabled, loading, empty.
6. Только после этого — коммит и переход к следующей странице.

Если я кладу референсы в `/references` (скриншоты сайтов), смотреть их как изображения и сопоставлять с результатом.

## 9. Качество и доступность

- Адаптив mobile-first, без горизонтального скролла.
- Контраст по WCAG AA, видимый focus, навигация с клавиатуры, корректные aria-атрибуты и alt.
- Семантическая вёрстка (header/main/nav/footer, правильные заголовки h1–h3).
- Анимации отключаются при `prefers-reduced-motion`.
- Единый стиль кода, TypeScript без `any`, компоненты переиспользуемые, без дублирования стилей.
- Производительность: `next/image`, ленивая загрузка тяжёлых блоков, без лишних зависимостей.
- Заполнить `<title>`/meta для каждой страницы.

## 10. Структура проекта

```
/src
  /app            # маршруты (публичные + /dashboard)
  /components     # переиспользуемые блоки и секции
  /design-system  # токены и базовые UI-компоненты
  /data           # моковые данные
  /lib            # утилиты, auth-контекст, форматтеры
  /styles         # глобальные стили
/docs             # design-direction.md, заметки
/references       # скриншоты референсов (если есть)
/public           # статические ассеты
```

## 11. План этапов (двигаться строго по порядку)

1. **Этап 1.** Инициализация проекта, зависимости, структура, git. Файл `/docs/design-direction.md` с 2–3 вариантами направления → ждать моего выбора.
2. **Этап 2.** Токены + базовые компоненты + `/styleguide` (обе темы).
3. **Этап 3.** Layout: Header (мега-меню, мобильное меню, переключатель темы), Footer, переходы между страницами.
4. **Этап 4.** Главная страница (эталон качества, довести до идеала).
5. **Этап 5.** Публичные страницы по группам: staking → tools → about/team/security → blog → docs/faq/contact/legal.
6. **Этап 6.** Фейковая авторизация и экраны входа/регистрации.
7. **Этап 7.** Личный кабинет: каркас (sidebar/topbar) → dashboard → остальные разделы.
8. **Этап 8.** Сквозной аудит: согласованность, адаптив, доступность, производительность, 404, пустые состояния.
9. **Этап 9.** Полировка анимаций и микро-взаимодействий, финальные скриншоты всех страниц.

После каждого этапа — краткий отчёт (2–3 предложения) и вопрос, продолжать ли.

## 12. Правила общения

- Если задача неоднозначна и ошибка дорогая (смена направления, структура) — спросить до начала.
- Если мелкая деталь — выбрать разумный вариант и пометить в отчёте.
- Не просить подтверждения на очевидные технические шаги.
- Не менять утверждённую дизайн-систему «по пути» без согласования.
