# CLAUDE.md — Staking Platform: Frontend Design Prototype

## 0. О проекте

Многостраничный сайт крипто-компании по стейкингу (рабочее название: **{BRAND_NAME}**, заменить позже).
Это **только дизайн-прототип**: без бэкенда, без базы данных, без реальных API и блокчейн-интеграций.
Цель — максимально убедительный, выверенный визуально и анимационно фронтенд, который можно показать клиенту/инвесторам и позже подключить к реальному бэкенду.

Язык интерфейса и контента сайта: **английский** (если не указано иное). Язык общения со мной: русский.

## 1. Жёсткие ограничения (никогда не нарушать)

- НЕТ бэкенда: никаких серверных баз данных, ORM, API-роутов с реальной логикой, внешних платежей, web3-кошельков, реальных запросов к блокчейну.
- НЕТ реальных секретов, ключей, `.env` с данными.
- Все данные (ставки, APY, TVL, балансы, транзакции, команда, статьи блога) — **моковые**, лежат в `/src/data/*.ts` и импортируются локально.
- Авторизация — **фейковая**: любая пара email/пароль «проходит», состояние хранится в `localStorage` (+ простой React Context). Никакой валидации «настоящих» пользователей.
- **Не показывать пометки «Demo data» / «Demo»** в интерфейсе (решение заказчика, 2026-10-17). Вместо них — нейтральные формулировки: «estimates, not an offer or a forecast», «reference prices», предупреждение о рисках в футере. Идентификаторы в коде (`DEMO_TODAY`, `demo_session`) пользователю не видны, их можно оставить.
- Не копировать у референсов (Ondo Finance, Spreadefi) тексты, логотипы, иллюстрации, названия продуктов. Берём только **принципы структуры и визуального языка**, всё содержимое оригинальное.
- Не выдумывать юридически значимые заявления (лицензии, аудиты конкретных фирм, гарантированную доходность). Использовать нейтральные формулировки + блок рисков.

## 2. Технологический стек

- **Next.js (App Router) + TypeScript**
- **Tailwind CSS** + CSS-переменные для токенов
- **Framer Motion** — анимации (появление секций, hover, переходы между страницами, счётчики)
- **lucide-react** — иконки
- **Recharts** (или аналог) — графики в дашборде на моковых данных
- **next/font** — шрифты (self-hosted через Google Fonts)
- Без UI-китов, которые навязывают «типовой» вид. Допустимо использовать Radix UI primitives (доступные dropdown/dialog/tabs) со своей стилизацией.

## 3. Обязательный порядок работы

1. **Перед любым фронтенд-кодом загрузить скилл `frontend-design`** и сформулировать дизайн-направление письменно (в `/docs/design-direction.md`).
2. **Сначала дизайн-система, потом страницы** (см. раздел 5). Страницы нельзя начинать, пока нет токенов и базовых компонентов.
3. **Одна страница за раз.** После каждой — визуальная проверка (раздел 8) и git-коммит.
4. Перед крупными шагами использовать Plan Mode и кратко согласовывать план.
5. Никаких «значений от балды»: цвета, отступы, радиусы, тени, размеры шрифта — только из токенов.
6. После каждого завершённого этапа: `git add -A && git commit -m "..."`.

## 4. Дизайн-направление

Референсы по духу (НЕ копировать, только ориентироваться):

**Ondo Finance — институциональный, «взрослый» финтех:**
- Крупная уверенная типографика в hero, короткий манифест-заголовок.
- Много воздуха, чёткая сетка, ощущение надёжности и «институционального качества».
- Полоса логотипов партнёров (бесконечный marquee).
- Блоки с живыми метриками (TVL, число активов, APY) с анимацией счётчиков.
- Секция «Trust & Security»: нумерованный список принципов (01–05).
- Карточки продуктов с метриками и кнопкой «Discover».
- Секции с цитатами партнёров, блок инсайтов/блога, подписка на рассылку, многоколоночный футер.

**Spreadefi — DeFi-стейкинг, продуктовая ясность:**
- Простая схема «как это работает» в 4 шага (Stake → Pool works → Revenue → Rewards).
- Акцент на пулах ликвидности, ежедневных выплатах, прозрачности и возможности вывода.
- Страницы: стейкинг, swap, API/для разработчиков, документация.

**Итоговый стиль (зафиксировать в design-direction.md):**
- **Сайт только в светлой теме** (решение заказчика; переключатель темы удалён). **Исключение — дашборд** (2026-10-19): тёмная тема, почти чёрная (`[data-theme="dark"]` в `tokens.css`, без синего оттенка; inverse-секции сайта остаются тёмно-синими). Выбор Light / Dark / System — в Settings → Appearance и кнопкой в Topbar; хранится в `localStorage.dashboard_theme`; `DashboardShell` ставит тему на `<html>` (порталы следуют), при уходе из дашборда — снова light; `themeInitScript` применяет тёмную до первой отрисовки только на `/dashboard*`. По умолчанию — светлая. Основной фон светлый, тёмные inverse-секции (`data-tone="inverse"`) чередуются со светлыми; для светлой серой полосы — `Section tone="subtle"` (так оформлен блок «Accounted for at every step» на главной, решение 2026-10-19); акцент — один фирменный цвет + нейтральные.
- Декоративная палитра `--topic-*` — для сгенерированных обложек (ECO. LEARN, новости на главной) и в дашборде для цветовых меток рядом с текстом: иконки-чипы (`IconChip`, `src/components/dashboard/tones.tsx`) по типу транзакции/категории уведомления/панели, цвет сети (`POOL_TONES`, один на сеть на всех страницах) в полосах состава и долях. Ещё — иконки мега-меню: серые в покое, при наведении/фокусе окрашиваются в свой тон (`icon`/`tone` у ссылок в `components/layout/nav.ts`), логотипы пулов там же — из серых в цветные. Плюс у каждой иконки своя короткая анимация при наведении (чистый CSS в конце `globals.css`, по классам Lucide `.lucide-*` внутри `[data-menu-icon]`; логотипы сетей крутятся как монета); новая иконка в меню — добавить ей анимацию там же. Тот же язык иконок на страницах (2026-10-19): `MenuIcon colored` — цветная плашка; анимация проигрывается один раз при появлении (`PlayOnView`) или при выборе (`data-icon-play`). Так оформлены `/tools` (карточки: как в меню, на телефоне сразу цветные), `/security` (5 принципов, «Keys and access», шаги инцидента через `ControlsList`/`StepsFlow` с `icons`) и `/contact` (подсказки — как в меню; темы формы и каналы — общая карта `components/contact/topics.ts`, выбранная тема подсвечивается своим цветом).
- Пустые состояния — маленькие иллюстрации в стиле обложек (`EmptyState art="positions|rewards|search|notifications|invites|keys"`, `EmptyArt.tsx`), работают и в тёмной теме дашборда; на 404 — картинка «сеть улетела с орбиты».
- `/validators`: полосы аптайма заполняются волной при прокрутке (CSS `.uptime-cell`, `[data-filling]` в конце `globals.css`), дни с инцидентами вспыхивают, проценты считают (`CountUp`). Никогда — для текста и состояний UI (для них success/warning/danger). Решение 2026-10-19.
- Избегать: фиолетово-розовых градиентов «по умолчанию», системных шрифтов, шаблонного «AI-вида», перегруженных неоновых эффектов.
- Шрифты (2026-10-21, выбор заказчика из 4 вариантов): **Geist** — всё (заголовки, лиды, текст, интерфейс), **Geist Mono** — цифры, адреса, хеши (`src/design-system/fonts.ts`, токены `--ds-font-display`/`--ds-font-mono`). Шрифта с засечками и курсива нет: прежний Source Serif 4 в лидах читался как курсив, токен `font-serif` удалён. Для превью ссылок — TTF Geist в `src/app/_og/fonts`. Не Inter/Roboto/Arial.
- Числа в дашборде — табличные (`font-variant-numeric: tabular-nums`).
- Стекло/размытие и тонкие границы — умеренно. Тени мягкие. Радиусы единые.
- Анимации: плавные, сдержанные (200–600 мс), easing единый; уважать `prefers-reduced-motion`.
- Появление контента на всём сайте — один стиль «подъём снизу» (кейфрейм `rise` в `globals.css`, решение 2026-10-19): `ScrollReveal` (в `(site)/layout`, области `[data-reveal-scope]` — main и футер) прячет блоки ниже первого экрана и поднимает их при прокрутке, появляющиеся вместе идут лесенкой. Блок — самый внутренний из: детей `.container-page` и `section`, ячеек `grid`, строк таблиц, `[data-reveal-item]` (поднимается целиком, внутрь не заглядываем); исключить — `data-no-reveal`. Состояние «ждёт» — удерживающая Web Animation, а не атрибут: React его не видит, гидрация не ругается. Переделку главной (пулы, сравнение, новый CTA, FAQ) заказчик отклонил 2026-10-19 — порядок блоков прежний. Шапки страниц и hero поднимаются при загрузке чистым CSS (`data-intro` на контейнере, дети по очереди). Новые страницы получают это автоматически, отдельный код не нужен.

## 5. Дизайн-система (создать первой)

Папка `/src/design-system` и страница-витрина `/styleguide`:

- **Токены** (CSS variables + Tailwind config): цвета (bg, surface, border, text, muted, accent, success, warning, danger), типографическая шкала, отступы (шкала 4/8), радиусы, тени, z-index, длительности/easing анимаций.
- **Тема**: сайт светлый; тёмные поверхности — inverse-секции (тёмно-синие токены в `tokens.css`). Дашборд дополнительно имеет почти чёрную тёмную тему (см. раздел 4).
- **Базовые компоненты**: Button (primary/secondary/ghost, размеры, loading), Input, Select, Checkbox, Toggle, Tabs, Modal, Dropdown, Tooltip, Badge, Card, Table, Tag, Accordion, Progress, Skeleton, Toast, Pagination.
- **Составные блоки**: Header (с мега-меню), Footer, Hero, StatCard (анимированный счётчик), LogoMarquee, FeatureGrid, StepsFlow, PricingTable/TierCards, TeamCard, BlogCard, CTASection, Newsletter, FAQ, TestimonialSlider, Breadcrumbs.
- **Дашборд-компоненты**: Sidebar, Topbar, BalanceCard, ChartCard, StakePositionsTable, RewardsFeed, ActivityList, EmptyState.
- На `/styleguide` показать все компоненты во всех состояниях (одна светлая панель на пример), включая обложки и блоки статей.

## 9. Качество и доступность

- Адаптив mobile-first, без горизонтального скролла.
- Плотность на телефонах (< sm, ~20% аудитории): секции `py-14`, крупные отступы (gap/mt/mb ≥ 10) задаются меньшими с `sm:`-значением для прежнего; типошкала h1/h2/display/lead — fluid; карточки гайдов и статей горизонтальные (обложка-квадрат слева). Десктоп и планшет не меняются.
- Мобильное меню (переделано 2026-10-20): шторка снизу (`MobileMenu`), выезжает пружиной, фон страницы размыт (`bg-scrim/60 backdrop-blur-md`), высота по содержимому, максимум 85dvh, дальше прокрутка; закрывается крестиком, тапом мимо, Esc или свайпом вниз за «ручку». Без аккордеонов: все пункты мега-меню списком под подписями разделов (Staking — сначала избранные пулы с APY), на планшете в две колонки; внизу Log in / Start staking (или Log out / Dashboard). Те же иконки, что в мега-меню (`MenuIcon`/`PoolMenuIcon`), серые, цветные у текущей страницы и при нажатии, анимации проигрываются при открытии (`[data-menu-play]`). При нажатии пункт подсвечивается фирменным синим (`active:bg-accent`), системная серая вспышка отключена.
- Модальные окна (`Modal`) на телефонах (< sm) — тоже шторка снизу: пружина, размытый фон, «ручка» для свайпа вниз (общие настройки в `design-system/sheet.ts`, их же использует мобильное меню); на планшете и десктопе — карточка по центру, при reduced motion — тоже.
- Контраст по WCAG AA, видимый focus, навигация с клавиатуры, корректные aria-атрибуты и alt.
- Семантическая вёрстка (header/main/nav/footer, правильные заголовки h1–h3).
- Анимации отключаются при `prefers-reduced-motion`.
- Единый стиль кода, TypeScript без `any`, компоненты переиспользуемые, без дублирования стилей.
- Производительность: `next/image`, ленивая загрузка тяжёлых блоков, без лишних зависимостей. Recharts грузится отдельно и только когда график рядом с экраном (`TimeSeriesPlot` через `next/dynamic` в `TimeSeriesChart`) — минус ~340 КБ на страницах с графиками. Общие компоненты шапки/лейаута импортируют дизайн-систему по прямым путям. Framer Motion — через `LazyMotion` (`MotionProvider` в корневом layout, движок `domMax` догружается в простое браузера): в компонентах только `m.*`, обычный `motion.*` в строгом режиме — ошибка. Анимация загрузки `[data-intro]` начинается с opacity 0.01 (не 0), чтобы LCP засчитывался с первого кадра. Lighthouse (мобильный, 2026-10-20, медианы 3 прогонов): доступность, best practices, SEO — 100, CLS 0; производительность ~50–56 (страница пула 46 → 52 после оптимизаций). Оставшийся тормоз — гидратация React (TBT 1,3–2,5 с при 4× замедлении CPU): это объём клиентских компонентов, а не размер библиотек; дальше — только перевод крупных блоков в серверные компоненты.
- Заполнить `<title>`/meta для каждой страницы.
- Превью ссылок: `opengraph-image.tsx` (общее в `src/app`, свои — для пулов, статей, гайдов) на общем рендере `src/app/_og/card.tsx` со шрифтами из `src/app/_og/fonts` (значения токенов продублированы там — держать в синхроне с `tokens.css`). `sitemap.ts` и `robots.ts` — только публичные страницы; дашборд, вход и `/styleguide` закрыты от индексации.
- Абсолютный адрес сайта — `NEXT_PUBLIC_SITE_URL` при сборке и запуске (`src/lib/site.ts`; на Vercel берётся сам). Для туннеля: `NEXT_PUBLIC_SITE_URL=https://<туннель> npm run build && … npm run start`.
